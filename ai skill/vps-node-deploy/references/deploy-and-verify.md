# Agent 执行细则：部署、导出、验证、排障

本参考不固定真实 IP、凭据、操作系统版本或安装路径。先发现环境，再选择方案。工具受限时说明范围，不用“可直接复制”的脚本代替实际部署成功。

## A. SSH 与环境检查

使用本机 SSH 客户端或可信 SSH 库，密码从安全交互输入。主机地址作为参数，不把用户提供的任意字符串拼接成可执行 shell。

Linux 只读检查示例：

```sh
cat /etc/os-release
uname -m
uptime
free -h
df -h /
ss -lntup
systemctl list-unit-files --type=service
date -u
```

查询现有代理服务及日志时只显示必要字段，避免打印私钥、UUID、完整 URI。检查防火墙时先确定存在 nftables、iptables 或 ufw，工具不存在不等于没有上游防火墙。保留 22/实际 SSH 端口规则。

已有 SQLite 面板数据库使用在线 backup API 等一致性方法备份。备份内容包含凭据，限制目录和文件权限。发现网站、数据库、面板等其他工作负载时保留它们。

## B. 部署路径

### 复用既有节点

核对入站协议、传输、端口、证书或 REALITY 参数和用户启用/到期/额度。检查客户端持有的是当前有效凭据。仅凭服务 active 不足以验收。

### 独立服务示例结构

可以采用 `/etc/<service>/config.json` 与 `/etc/systemd/system/<service>.service`；实际名称和路径在报告中记录。专用无登录账号替代共享 nobody，配置目录 750、文件 640（root 与服务组），二进制可执行但服务账户不可改写。权限随所选实现的实际需求调整。

最小 systemd 单元应具备 ExecStart、Restart=on-failure、RestartSec、适合的 User/Group 和启动依赖。可加入 NoNewPrivileges、PrivateTmp 等与实现兼容的限制。绑定低端口时使用必要的能力或支持的方式，不盲目改成 root 常驻。

先运行所选程序的配置检查，再启动、检查监听和服务日志；配置开机启动与真实重启验收分别标注。旧面板目录里的二进制若被独立服务复用，必须记录升级耦合，后续更新时两套都复测。

SS2022 AES-256 需要 32 字节密码学随机密钥并按协议编码。VLESS/REALITY 使用独立生成的凭据、公私钥与正确目标参数；不能复用示例密钥。协议细节应核对当前官方文档，不凭记忆硬套最新版本。

## C. 配置与链接

Clash 需要 proxies、proxy-groups 和明确 rules。默认可先做局域网直连、其余走节点的简单验证配置，并告诉用户这不是完整国内外分流；如用户明确要求地域分流则按需求配置。导入文件可能被应用复制，修改源文件不自动改变活动订阅。

对 SS2022：使用 SIP002 的明文 userinfo 形式，对 method 和 password 分别百分号编码，不把 SS2022 userinfo 整体做 Base64URL。示意结构：

```text
ss://<percent-encoded-method>:<percent-encoded-password>@<host>:<port>#<encoded-name>
```

IPv6 地址要正确加方括号。URI 生成后解析回读，逐字段与配置比对，不打印密钥。为 v2rayN 和 Shadowrocket 输出同样的受支持 URI 是正常的，不需要人为创建不同服务。

二维码用本地库生成；核对源字符串，具备解码工具时增加二维码解码回读。没有手机扫码验证就标注待实测，不宣称二维码已在 iOS 验收。

如用户明确需要本机下载 URL，辅助服务只绑定回环地址并返回指定文件，不暴露目录；停掉辅助进程不影响已导入节点，但订阅更新会失败。手机不能使用电脑的 localhost URL。公网订阅属于另外的托管需求，应先明确访问控制和长期可用性。

## D. 分层测试

检查端口空闲再启动临时内核，仅绑定 127.0.0.1。强制测试请求走目标节点，不借用户当前路由结果推断。用 curl 的显式代理参数和空 NO_PROXY，避免本地 DNS/环境变量造成误判。例如：

```text
curl --proxy socks5h://127.0.0.1:<测试端口> --noproxy "" --max-time 20 <目标URL>
```

Windows 使用 curl.exe；输出正文到 NUL，Linux 可用 /dev/null。记录 HTTP 状态、curl 退出码、time_total、time_starttransfer，错误脱敏。经代理请求可信出口查询服务，核对与 VPS 预期出口是否一致（若供应商有 NAT，进一步确认其配置）。

候选目标：Google generate_204、GitHub 首页、YouTube 首页和用户自己的目标。不主动提交用户账号登录表单。目标返回 403 是站点拒绝该请求，可能有多种原因；不能单凭这一条认定 IP 被封。

测试结束用 finally 停掉临时进程。确认原服务状态未受影响，用户实际客户端的配置选择正确。若只测独立内核，不声称已经操作应用 GUI。

## E. iPhone 专项排障

先取：节点名称/服务器、Shadowrocket 版本、网络类型、运营商、路由模式、实际错误和是否所有网站失败。收集截图需提醒遮蔽密钥。

对照顺序：蜂窝数据权限 → 节点是否选中 → VPN 是否建立 → 临时“代理”模式 → 浏览器实际请求 → Wi-Fi/蜂窝对照 → 日志定位 DNS/握手/超时。

延迟测试可能仅检查入口可达，不能代替代理认证和网页请求。Wi-Fi 可用而蜂窝失败只提示网络路径差异，不足以直接认定运营商封锁。若电脑可达，仍要从手机请求时段日志验证；避免一开始就重装 VPS。

## F. 速度、流量与故障分支

限量测 VPS 自身下载与本地经代理下载，尽量同目标、同样本、相近时间；记录消耗量和开销。小文件平均速率受握手影响，不是峰值。服务器快、本地慢只支持链路或本地因素的假设。

不要把网卡累计收发、某个面板计数、月账单额度混在一起。独立服务可能不被面板计量，重启可能改变计数；新增监控不能还原过去用量。

| 证据 | 下一步 |
| --- | --- |
| SSH 不通 | 服务状态、端口、主机与云防火墙、接入网络 |
| 配置校验失败 | 当前版本 schema 和具体错误，不直接重装 |
| REALITY authentication failed | 凭据/SNI/shortId/flow/时间/具体内核兼容性 |
| 显式代理可用、应用不通 | 系统代理/TUN、分流、应用代理机制与错误 |
| 两个客户端运行 | 检查谁实际接管；运行本身不等于冲突 |
| 首页通、视频不通 | 资源域名分流与播放器错误，不能直接说网坏了 |
| 速度波动 | 多时段、分段、丢包和负载证据；每次只改一个变量 |

## G. 报告与回滚

报告包含服务器/客户端版本、服务名、配置/单元/备份路径、使用端口、启动状态、实测时间和结果、未验证范围。不要写 SSH 密码、节点密钥、私钥。记录停用新服务会影响哪些客户端。

失败回滚恢复本次修改的文件权限、配置、服务和规则；保留备份。撤销新增入口不应停止不相关应用。不能用“原节点没改配置”替代检查它是否还运行。
